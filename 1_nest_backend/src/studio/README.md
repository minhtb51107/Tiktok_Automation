# Content Studio

The UI-01 descriptions below are retained as historical baseline notes. Current Editor behavior is documented in **UI-04.3 — Professional Editor** at the end of this file. Script and Voice are now implemented as explicit user actions; opening the Editor does not call AI/TTS or start production workflows.

## UI-04.2 Threads visual, topic and public library

The user-confirmed validation project is `35b8a880-b8b5-49ec-be42-0991228eb45e` (ledo.duta, twice_._not, quyenminh.le, dang.hoang88, minggthuan). It is distinct from the earlier `a6e7cbe3...` project. Studio now preserves `?session=<UUID>&step=Video%20Editor` deep links and shows the active ID/revision. Never infer the active project from a generic `/studio` URL.

Topic is a separate optional header field. Extraction recognizes exactly matched target links `/search?...serp_type=tags&tag_id=...`; it never assumes every first line is a topic. Original/raw text remains intact. POST `/:id/topic/:itemId` explicitly confirms topic/body and optionally strips an exactly matching raw/offline-expanded prefix from spoken text. Item revisions, manual locks, stale audio and spoken approval hashes remain enforced. Ambiguous changes need review; locked spoken corrections require a separate confirmation. Existing audio files are never deleted by topic changes.

The shared scene visual contract stores card X/Y/width/scale/padding/font/gap, meme selection/placement/timing, background and voice/SFX controls. Default card Y is 288 on the 1080×1920 canvas (15%). Long text is paginated visually with no narration-duration estimation, no clipping and no claim of word-level alignment. Meme/GIF sits outside and below the card. Null engagement values are hidden, zero remains zero, source compact counts are preserved, and video dates use dd/mm/yyyy. Missing media/avatar never prints UNAVAILABLE inside the video.

GET `/api/studio/public-assets` inventories actual files; hashed asset URLs stream the existing originals with range support. Category/search/preview do not copy, move or delete the public directory. FFprobe resolves durations of selected video/audio only. Background video is muted and cropped to cover the canvas; SFX/BGM are independent measured layers, with BGM default gain 0.08 and a maximum of 0.25. These gain controls do not replace a loudness/ducking validation gate. Narration still requires approved spoken text and matching audio in the same project; never borrow it from another session.

PNG/JPEG/WEBP/GIF uploads validate MIME, signature, dimensions and single-frame FFmpeg decoding. Errors distinguish unsupported type, MIME mismatch, size/dimensions and decode failures. Each user upload/retry has a request ID; content hashes still deduplicate files. DELETE `/:id/media/:assetId` requires revision, `confirm:true` and matching sha256. It refuses references in scenes, source items, prepared snapshots or other sessions, non-owned/public assets, changed hashes, symlinks and paths outside the session's media directory. Only explicitly confirmed unused uploaded files are removed; source, public media, sessions and voice audio are never cleaned up here.

Animated GIFs use browser image playback: visibility timing is controlled by timeline frames, but animation-phase fidelity after seeking/export is not yet validated. No MP4 rendering or publishing is enabled. This project initially has no Kokoro assets/approvals; successful SFX/BGM preview must not be reported as live voice synchronization.

## UI-03.3 / UI-04 progress and real project editor

Studio now uses persisted lightweight polling jobs: POST `/api/studio/sessions/:id/jobs` with `{operation,input}`; GET the session's `/jobs` or `/api/studio/jobs/:jobId`; POST `/api/studio/jobs/:jobId/cancel`. Legacy synchronous operations remain compatible. Admission is deduplicated using operation/input/session revision, with one sequential job queue. Refresh never starts a second job. Interrupted jobs on server restart become FAILED and are never silently retried. QUEUED/RUNNING/WAITING_REVIEW/SUCCEEDED/FAILED/CANCELLED are recorded with stage, measured steps/counts, timing, warnings and events. ETA stays null. Copy Job Report / Export Jobs JSON need no external API. Queued cancellation prevents execution; a running atomic operation/batch completes and retains artifacts before becoming CANCELLED, with this limitation explicitly reported.

Source extraction, offline/live normalization, voice/runtime/batches, image upload and preview preparation use the shared job store. Kokoro reports actual Loading model/Synthesizing events from its existing sequential worker, followed by FFmpeg processing, FFprobe validation and asset saving. A cache hit does not fabricate model-loading events. No render job is enabled.

Video Editor maps selected real Studio items by stable ID to StoryboardScene, existing buildVideoTimeline, createRemotionPreviewRequest and SeriousTimelinePreview inside @remotion/player. The optional threadsCard contract preserves public metadata, missing states and zero counts; old preview compositions retain their original fallback presentation. Matching spoken text hash, voice, speed, approval and measured manifest duration gate audio use. Generated but unapproved audio is preview-only and explicitly warned; missing audio gets an explicit user-set visual-only duration (default 3000 ms), never a guessed speech duration. Padding is calculated solely by the existing timeline engine. Subtitles are not invented from speech text; this MVP previews the Threads display card without word-level transcription.

Editor settings have independent scene order/enabled flags, padding/gap and local media assignment; they do not deselect or reorder Source items. Display text edits preserve original/spoken text and apply manual locks/revision checks. Save invalidates the prepared timeline; Prepare verifies referenced files and persists the new storyboard/timeline. Reload reconstructs current props from persisted source/settings/assets. Source selection and original extraction remain intact.

PNG/GIF uploads are bounded to 10 MB, 8192 px per side and 24 megapixels. Signature/dimensions and a single-frame FFmpeg decode are validated before accepting the manifest. Project-scoped content hashes deduplicate uploads; the project library reuses files across scenes and never scans arbitrary machine directories. Files/audio are never cleaned up here. Remote avatars/images may expire and show explicit unavailable placeholders; source video remains a reference. Animated GIF browser playback is not frame-accurate export validation. These and missing/unapproved audio are Render blockers, not production-ready claims. The player mounts only active/nearby audio sequences with bounded premounting, rather than preloading the entire timeline.

## UI-03.2 restart, multi-voice and speed

`npm run studio:start` loads optional `.studio-data/runtime.local.json` before checking port 3000. This ignored local JSON accepts only STUDIO_PYTHON, STUDIO_KOKORO_SOURCE, STUDIO_KOKORO_MODEL, STUDIO_KOKORO_CONFIG, STUDIO_KOKORO_VOICE_DIR and STUDIO_TTS_DEVICE; explicit environment values take precedence. Keep private paths there, never API keys. No Windows startup service, model preload or inference is registered. Stop with Ctrl+C in the terminal; before any restart inspect the listener owner and stop only this project's server.

Shared `voice-settings.ts` defines min 0.5, max 3.0, step 0.05 and SERIOUS default 1.2. Existing saved speeds are preserved. FFmpeg uses chained atempo above 2x (3x = 2 × 1.5); changing only speed reuses the original base WAV and never invokes Kokoro. FFprobe measures final duration and volumedetect rejects silent outputs. Regenerate explicitly forces a new base without deleting earlier files. Exact repeated settings reuse one manifest; stale history remains playable for comparison and cannot be mistaken for current audio.

Voice choices come from the installed Kokoro source catalog plus real local `.pt` files. Missing packs are visible but disabled; no voice download happens from the UI. Per-scene settings and bulk settings (`SETTINGS_ALL` with optional selected `itemIds`) share validation. Generate All awaits each scene with concurrency one. Model weights are retained across voice changes; only the small voicepack tensor is swapped. Preflight is cached for five minutes when local file sizes/mtimes and configuration are unchanged, avoiding repeated Torch processes next to an inference worker. The worker still exits after 60 idle seconds.

Approval of spoken text is independent of speed/voice and is not revoked by those setting changes. Ambiguous `t/đcđ/clm/cmn` remain visibly flagged even without a proposal; bulk approval skips them. A single explicit TTS approval is for listening, not production approval. Copy Report and JSON export on the Voice stage describe persisted runtime, settings, durations, histories and errors. Live verification uses a separate labelled smoke project, preserving all existing projects/audio.

UI-02B / UI-03: LIVE normalization remains Hugging Face Router/Qwen. HTTP 402 persists a redacted diagnostic and BLOCKED_BILLING; subsequent LIVE requests in that session are refused without a provider retry. No credit purchase, provider switch or account modification occurs. `{revision,mode:'OFFLINE'}` on the propose endpoint uses conservative whole-word rules, explicitly labelled OFFLINE, with EXPAND/KEEP/OMIT_SPOKEN/REVIEW_AMBIGUOUS and no auto-apply. GET `/:id/normalization-quality` contains nine rule cases, five real-target snapshots, expected/actual and human-review ambiguities.

Voice uses POST `/api/studio/sessions/:id/voice-runtime` for local preflight and POST `/:id/voice/:itemId` with `{revision,action,...}` for APPROVE_SPOKEN, SETTINGS (`voice`, `speed` 0.5–3.0), GENERATE (`regenerate:true` for fresh output), APPROVE_AUDIO (`assetId`). Source text approval is separate from normalization acceptance. Audio manifests include hash, generation revision, voice/speed/model version, measured FFprobe duration, file reference and approval. Text/voice/speed changes invalidate affected audio only. Only valid approved audio enters VideoProject.audioAssets. Assets and approved files are never deleted; `GET /:id/voice-gc-preview` lists only session-scoped orphan temp files older than 24h and performs no cleanup.

Configure an existing runtime using STUDIO_PYTHON, STUDIO_KOKORO_SOURCE, STUDIO_KOKORO_MODEL, STUDIO_KOKORO_CONFIG, STUDIO_KOKORO_VOICE_DIR and optionally STUDIO_TTS_DEVICE=cpu|cuda. VOICE_DIR contains actual `<voiceId>.pt` files. The voice catalog is parsed from the real source VOICES dictionary; declared voices are not runnable choices until imports, local model/config/voicepack are verified. No install or model download is automatic. Bridge network access is blocked, including transitive model downloads. Model worker is sequential, reuses one model safely, is terminated after 60 seconds idle, and exits if the parent process dies. FFmpeg atempo adjusts speed from base audio and FFprobe measures final duration; no word-count duration estimation is used. Cache is scoped to the session and keyed by text/config/model/voicepack identity and speed. Regenerate never overwrites referenced output.

Source/Script/Voice Copy Report and JSON export share StageReport. UI/backend contract tests use MOCK runtime and never prove real inference. Historical UI-02B preflight was BLOCKED_RUNTIME with Python 3.12.10; UI-03.2 discovers the configured Python 3.14.6 runtime and real local models independently. Explicit LIVE smoke scripts store measured results in ignored `.studio-data/reports/ui032/`; never infer live readiness from Jest alone.

UI-01.3 / UI-02A: Source cards display original text, public avatars/media and labelled engagement observations. Counts are mapped from the exact target card's SVG title + enclosing button text, never from numeric order. `fields` distinguish AVAILABLE / NOT_PRESENT / UNAVAILABLE / UNVERIFIED and preserve the raw compact count (e.g. rounding). POST `/:id/metadata/:itemId` with `{revision}` explicitly refreshes that target only, appending immutable `metadataObservations`; `rawExtraction` and originalText remain unchanged. A METADATA manual lock blocks automatic replacement of corrected metadata.

Script supports selected items in Source order. POST `/api/studio/sessions/:id/script/:itemId/propose` with `{revision}` makes exactly one Hugging Face request (existing HUGGINGFACE_API_KEY, Qwen model; no production DB). No request occurs on fetch, load or step navigation. JSON source text is untrusted data, not instructions. Output schema, item identity and ambiguous t/clm/đcđ are validated. Semantic correctness still requires human review. Token usage is recorded when returned; estimated cost is null because verified prices are not configured. Errors persist safely without provider response bodies/headers.

POST `/api/studio/sessions/:id/script/decision` accepts `{revision,runId,action}`. ACCEPT checks item revision/input and refuses a spoken lock; REJECT changes only the proposal. ACCEPT_LOCKED is a distinct explicit user-confirmed replacement of locked spoken text; approval is audited and the lock remains set. No decision changes originalText, displayText or other items. GET report with `?stage=SCRIPT` includes selected content, proposals, changes, ambiguity, approval and runtime usage. Report generation elapsed (local read/assembly) is separate from stage extraction/inference elapsed.

Default Jest tests mock AI completely. `test/studio-script-ui.cjs` checks real source cards and a clearly labelled browser-only mock proposal; it never calls an AI provider or writes synthetic proposals to real sessions. Real provider availability has not been validated by this offline test.

UI-01.2: Source extraction defaults to TARGET_ONLY. DOM target identity matches the exact permalink ID, never a text prefix. Missing/ambiguous identity returns unresolved; public canonical metadata can provide a partial target when it independently matches the resolved permalink. Context candidates live separately in attempts; WITH_CONTEXT exposes auxiliary candidates and each Add action explicitly imports a chosen candidate. Target-only content is not automatically expanded into editors.

POST `/api/studio/sessions/:id/exact-copy` is an explicit live extraction action: it preserves the original session unchanged, creates a derived project, rechecks its supplied URLs and transfers matching user edits/locks. The old items are also archived in the derived session. Loading a project or report never invokes extraction.

GET `/api/studio/sessions/:id/report` returns `{report,markdown}` in the existing data envelope. StageReport supports SOURCE/SCRIPT/VOICE/EDITOR/RENDER/PUBLISH; only Source is implemented. Reports include run/revision/timing/counts, exact target evidence, unavailable metadata, warnings and measured metrics. Counts distinguish project items from context occurrences that were not explicitly added. Costs remain null until measured. Raw browser errors, runtime paths, cookies, profiles, headers and env values are not exported. Source URLs and public content are preserved; URL query strings are omitted from exported links. Save edits before Copy Report or Export JSON.

Open http://127.0.0.1:3000/studio (PORT can change the port). One Nest server serves React and the API. `studio:start` checks the port before starting and refuses a second backend. Stop the foreground server with Ctrl+C. For restart: stop the verified project process, build sequentially, then run `npm run studio:start`. Inspect ownership first with `Get-NetTCPConnection -LocalPort 3000 -State Listen` and `Get-CimInstance Win32_Process -Filter 'ProcessId=<PID>'`; never stop an unrelated process.

Data lives in the ignored backend `.studio-data` directory. Back up this directory to preserve projects. Browser edits require Save; reopening reads the persisted session. No database is used. UI-01.1 accepts canonical/share URLs with query parameters and legacy threads.net links; each redirect is bounded, HTTPS/domain checked, DNS pinned. Public HTML metadata survives browser failures. `attempts` retain original/resolved/canonical URLs, stage diagnostics, timing and public raw records. Missing fields use null; source/context cards can have UNKNOWN type when reply hierarchy cannot be verified. Manual metadata/media corrections never replace rawExtraction. CDN URLs can expire. No credential or login is used. STUDIO_BROWSER can point to an existing browser; no automatic download occurs.

API responses use the existing `{success,data}` envelope. Humans and agents use the same operations:

- POST `/api/studio/sessions`: create.
- GET `/api/studio/sessions`: list.
- GET `/api/studio/sessions/:id`: load full session.
- PUT `/api/studio/sessions/:id`: `{revision,title,items}`. Item patches accept only ID, selected, displayText and spokenText, in desired order. Originals/source IDs remain server-owned. Stale revision returns 409.
- PUT same route: `{revision,manual:{text,author,comments,url?}}`; comments are separated by newlines.
- POST `/api/studio/sessions/:id/fetch`: `{revision,urls}`; 1–5 canonical HTTPS Threads post URLs. Explicit request only. Failed extraction is persisted as ERROR with visible messages; successful URLs are retained.

Only one mutation/extraction is admitted at a time. No background jobs, AI, TTS, database, Discord or publishing modules are imported. Controlled scraper requests are restricted to HTTPS Threads/Meta CDN hostnames. Browser/model downloads are not part of Studio startup.

`StudioSession.project` uses VideoProject v1; original posts/comments and candidates are separate from editable StudioItems. Stable source references, revision and text locks support future storyboard generation. The editor boundary is VideoPreviewProps for the existing SeriousTimelinePreview and @remotion/player. Script/Voice/Editor/Render/Publish are explicitly unimplemented in UI-01.

Current limits: local single-process storage; no authentication, deletion UI, undo history, batch JSON import, automatic source refresh, or production rendering. Media references are shown as text; remote media is not fetched by the UI. Manual imports without URLs use an empty canonicalUrl to indicate unavailable provenance. Live extraction requires separate approval and has not been used for UI-01 validation.

## UI-04.3 — Professional Editor (local preview)

Open a project using `/studio?session=<id>&step=Video%20Editor`. Scene list and the category-based asset browser share the left panel; the portrait Player stays in the center; the right Inspector follows a canvas object or timeline clip selection. Panels scroll independently at 1366×768 and 1920×1080. Studio appearance is a browser preference; each card's LIGHT/DARK appearance and line height are saved in the project's editor settings.

The browser and backend use the same pure `buildStudioPreview` mapper, `editorSettings` defaults and timeline engine. Inspector edits update a local draft immediately without preparing persisted jobs on each keystroke. Save project validates revisions through the existing editor API, persists the draft and runs the existing preview preparation job. Undo/Redo keeps at most 30 in-memory edits; history resets after saving/reopening. Unsaved navigation/reload requires confirmation. A disabled scene is omitted from the computed timeline while its settings remain stored.

Body wrapping uses measured local Arial glyph advances rather than fixed character counts. Long content is paginated in the existing composition; neither original source nor narration is rewritten. Reset Layout restores the bounded top-aligned preset. Safe-area guides are approximate editing overlays, not export elements or a guarantee for every TikTok device/UI.

Asset pickers default to the matching category (Background, Meme/GIF, SFX, BGM). Other files are preview-only; public originals cannot be deleted. The metadata endpoint `GET /api/studio/public-assets/:id/info` measures only selected local assets and caches ffprobe results. No full directory copy or model/browser download is required. Uploaded assets continue using the existing reference-checked deletion API and confirmation. BGM has gain/mute controls; fades/ducking are not implemented. GIF phase accuracy after arbitrary seeks is not export-validated. Missing voice remains explicit; no audio is borrowed from another session or auto-approved.

Validation artifacts for UI-04.3 live in ignored `.studio-data/reports/ui043/`; generated Studio/build files are ignored. No production render, publishing, AI or TTS call is made by these editor controls.


## UI-04.4 — Voice draft, direct editing and continuous background

Voice preflight discovers installed voices; the first Voice workspace entry checks runtime if this session has no result. Discovery is distinct from the number of generated audio samples. Existing local runtime configuration is reused; startup never synthesizes speech. Single-item GENERATE accepts draft:true to synthesize unapproved spoken text without setting spokenApproval or approvedAt. Such assets carry purpose:DRAFT, remain pending for production, and can be listened to and used by preview. Existing explicit approval routes retain their gates. Bulk generation continues to mean reviewed scenes; it is labelled accordingly. Voice speed remains the shared 0.5–3.0x contract, step 0.05.

Uploads accept an explicit category MEME/GIF/BACKGROUND/SFX/BGM/UPLOADS. Image limit is 10 MB; audio/video 50 MB. Extension, MIME, signature, stream metadata and a bounded decode are checked before accepting a manifest. PNG/JPEG/WEBP/GIF and MP4/WEBM/MP3/WAV/M4A/OGG have explicit handling. New uploads appear first in their category and are deduplicated by content hash within the session. PUT /api/studio/sessions/:id/media/:assetId/category uses revision checking and refuses to recategorize referenced files. Remove from timeline never removes the physical file. Deletion still requires explicit confirmation, matching hash, ownership and no project/source references; public files have no deletion UI.

Canvas card/meme selection supports pointer drag/resize, center snapping, aspect lock for newly assigned images, Inspector editing and one Undo step per gesture. Data edits are blocked during playback and pending saves/jobs. Timelines support clip selection/move/left-right trim, scene/clip snapping, zoom, ruler/playhead scrubbing and Delete/Undo. Scene-owned card/meme/voice/SFX clips remain bounded to their source scene; this is non-ripple editing. Scene order is changed in the existing scene list. Global background/BGM can span scenes. Dragging a categorized asset onto its matching track assigns it to the scene/time under the drop.

EditorSettings, VideoProject and VideoPreviewProps carry optional backgroundTracks. Each clip has stable id, assetId, startMs/durationMs, sourceInMs/sourceOutMs, loop/enabled, optional seed/offsetMs. These are serializable settings persisted through the same revision-checked editor API that agents can use. Missing backgroundTracks in an older client preserves saved tracks; explicit [] clears them. The existing timeline engine remains the authority for composition duration. Global background sequences sit outside the scene map and reuse Remotion Video; later overlapping clips override earlier clips. Existing per-scene background choices are retained for fallback. Split preserves source phase, including loop phase. Extending to the whole timeline preserves the chosen source in. Source auto-selection is a deterministic seeded hash over measured available duration, not AI quality assessment. Inspect/seek uses local metadata and native video streaming, not a full frame extraction.

Chromium can floor rational seek times to microseconds and display the preceding PTS (verified at 43.966666 versus PTS 43.966667). ContinuousBackground corrects only a sub-2-microsecond undershoot after seeking. It does not change frame count, playback rate, user source in/out, or add a whole-frame offset. Browser validation uses requestVideoFrameCallback and hashes of actual decoded pixels, in addition to currentTime. Safe-area and manipulation overlays remain outside the Remotion composition.

Threads metadata/original/spoken text are not changed by layout. Body weight is explicitly regular 400 and date is inline in the header. Exact comparison against the missing original Threads screenshot is still a user review item. GIF phase accuracy and MP4/export behavior remain outside this preview-only task. Use the existing approved-audio and publishing gates before production.

Task-specific verification evidence is in ignored .studio-data/reports/ui044. Smoke scripts there are single-session task artifacts; do not rerun them against later manual edits without a fresh snapshot. No render/publish/Hugging Face API/model download is part of these checks.
